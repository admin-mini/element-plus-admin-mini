# 完善用户添加与角色分配功能

## Context（背景）

现有 `src/views/sys/user/index.vue` 已有“邀请加入 / 新增用户”的按钮入口，但 `modules/form.vue` 目前是残缺的：
- 表单字段裸绑定，无组织机构树选择、无角色分配组件。
- 提交逻辑错误复用了 `roleApi.addRole / editRole / getRoleDetail`（角色管理接口），并非用户接口。
- 多租户邀请模式没有实现。

系统支持多租户：
- 当 `.env` 中 `TENANT_ENABEL = true` 时走“邀请加入”模式（先按账号查询平台用户，再将其加入当前租户并分配组织、角色）。
- 当 `false` 时关闭多租户，直接走普通新增用户（填用户名/密码/组织/角色）。

目标：完善用户新增/编辑表单，补齐组织选择与角色分配，并实现两种租户模式的入口差异，同时修正环境变量开关。

## 关键结论（已从 swagger 确认的接口契约）

- `POST /sys/role/userChildrenRole` → 用户可授权角色列表，返回 `CommonResult<List<SysRoleDTO>>`，`SysRoleDTO = { id, name, code, weight }`。无入参。
- `GET /sys/org/tree` → 我有权使用的组织结构列表（项目已有 `orgApi.getOrgTree()`），返回带 `children` 的树，节点 label 字段为 `orgName`。
- `GET /fileclient/queryUserByAccount?account=` → 邀请模式按账号查询平台用户，返回 `CommonResult<SysAccountSimpleResult>`，`SysAccountSimpleResult = { username, nickname, phone }`。
- `POST /sys/user/add` 参数：`roleIds[]`、`username`、`password`、`name(必填)`、`phone(必填)`、`email(必填)`、`nickname`、`orgId(必填)`、`gender`、`birthday`。
- `POST /sys/user/edit` 参数：`id`、`roleIds`、`name`、`phone`、`email`、`nickname`、`orgId`、`gender`、`birthday`。
- `GET /sys/user/detail?id=` 返回 `SysUser = { id, username, name, nickname, gender, birthday, phone, email, orgId, status, ... }`。

请求风格说明：项目所有 POST 均以 JSON body 发送（见 ajax 拦截器/现有 api 封装，如 `enableUser/deleteByIds` 均可用），swagger 中 `in=query` 为框架展示问题，继续沿用 JSON body 约定。

env 说明：Vite 仅把 `VITE_` 前缀变量注入 `import.meta.env`，而 `main.js` 中 `$env = import.meta.env`。当前 `.env` 的 `TENANT_ENABEL`（拼写错误且无前缀）无法被读取，导致开关恒为 false。需要修正。

## 实施步骤

### 1. 修正环境变量开关
- `src/../.env`：将 `TENANT_ENABEL = true` 改为 `VITE_TENANT_ENABLE = true`（加上 `VITE_` 前缀并统一为 Enable 拼写，保证注入 `$env`）。
- `src/views/sys/user/index.vue`：两处按钮判断由 `$env.TENANT_ENABLE` 改为 `$env.VITE_TENANT_ENABLE`。

### 2. 新增 / 补充 API
- `src/api/sys/role-api.js`：新增
  ```js
  /**
   * 用户可授权角色列表
   */
  export function getAssignableRoles() {
    return request("userChildrenRole", {}, "post")
  }
  ```
- 新建 `src/api/fileclient.js`（沿用 `baseRequest` 风格，URL 前缀 `/fileclient`）：
  ```js
  import baseRequest from './base-request.js'
  /**
   * 按账号查询平台登录用户（邀请模式）
   */
  export function queryUserByAccount(account) {
    return baseRequest("/fileclient/queryUserByAccount", { account })
  }
  ```

### 3. 重写 `src/views/sys/user/modules/form.vue`
沿用项目现有组件规范（`admin-dialog-content`、`admin-space`、`el-form`、`select-dict`、`el-tree-select`、`el-select`）：

- **props**：`row`（编辑行）、`isTenant`（由 index.vue 传入，即 `$env.VITE_TENANT_ENABLE` 布尔值）。
- **两步弹窗（新增 + 租户模式）**：当 `props.isTenant && !row?.id` 时，先显示账号查询区（仿参考项目 `ClientUserQuery`）：
  - 输入账号 → 调 `queryUserByAccount(account)`。
  - 成功拿到 `username/nickname/phone` → 预填 `username`(只读)、`name=nickname||username`、`phone`，并注入 `email`（必填，手动录入）。
  - 未找到 → 提示重新查询。
- **正式表单字段**（新增/编辑共用）：
  - 所在部门：`el-tree-select`，`:data="orgTree"` 来自 `orgApi.getOrgTree()`，`:props="{value:'id', label:'orgName', children:'children'}"`，`check-strictly`，绑定 `formData.orgId`。
  - 用户角色：`el-select multiple`，`:data` 来自 `roleApi.getAssignableRoles()` 扁平化后的 `[{id,name}]`，绑定 `formData.roleIds`。
  - 普通模式新增额外显示：`用户名(username)`、`密码(password)`（必填）。
  - 其余：姓名 name(必填)、手机号 phone(必填)、邮箱 email(必填)、昵称 nickname、性别 gender(`select-dict` 用 `$dict.sys_user_sex` 或 common 字典，如项目无则保留输入)、生日 birthday。
- **编辑回显**：`onMounted` 当 `row?.id` 时调 `userApi.getUserDetail(row.id)`，填充 `username/name/nickname/gender/birthday/phone/email/orgId/status`；`roleIds` 若返回中存在则回显。
- **提交**：`userApi.addUser` / `userApi.editUser`，payload 含 `roleIds/orgId/username/password/name/phone/email/nickname/gender/birthday/id`，成功后 `emits('success')`（父级刷新表格）。租户模式下不传 password。

### 4. `src/views/sys/user/index.vue`
- 仅更新两个按钮的 env 引用为 `$env.VITE_TENANT_ENABLE`；`handleAdd`/`handleJoin` 打开 form.vue 时传 `isTenant` prop（`handleJoin` 为普通模式传 `isTenant=false`，`handleAdd` 为租户邀请模式传 `isTenant=true`）。

## 复用与约定
- `baseRequest` 统一请求封装，响应已解包为 `{code, data, msg}`。
- 组织树接口复用现有 `orgApi.getOrgTree()`（label 用 `orgName`）。
- 表单弹窗组件规范参考 `src/views/sys/org/modules/form.vue`、`src/views/sys/user/post.vue`。
- 邀请查询交互参考 `D:\client_project\beijing_qiangsheng\agri_net\agri-dev\qslinks-admin-ui\src\views\sys\user\form.vue`（仅借鉴其两步查询思路，组件均落地为本项目 Element Plus 风格）。

## 验证

1. 启动前端 dev（`npm run dev`），打开“系统管理 > 用户管理”。
2. **租户模式（`VITE_TENANT_ENABLE=true`）**：
   - 点“邀请加入”→出现账号查询→输入平台账号→确认→表单预填 username/name/phone→填 email、选组织、勾选角色→保存→列表出现该用户且 `orgName/roleNames` 正确。
3. **普通模式（`VITE_TENANT_ENABLE=false`）**：
   - 点“新增用户”→直接填用户名/密码/姓名/手机/邮箱→选组织、勾选角色→保存成功。
4. **编辑**：点“编辑”→组织机构与角色正确回显→修改保存成功。
5. 后端可在 `http://localhost:8098/doc.html#/系统管理/角色控制器/post__sys_role_userChildrenRole`、`.../get__sys_org_tree`、`.../get__fileclient_queryUserByAccount`、`post__sys_user_add`、`post__sys_user_edit`、`get__sys_user_detail` 核对调用行为。

## 备注/风险
- 编辑回显时若实际 `detail` 未返回 `roleIds`（swagger 的 SysUser 定义未含），角色将不预选；实现时做大兼容（有则回显，无则空）。若确实缺失，可在验证阶段确认是否有其他取用户角色接口。
- `gender/birthday` 字典/控件按项目现有字典实现，缺失则保留为手填输入。
